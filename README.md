# ForteBank Video Analysis

Локальный сервис анализа видеозаписей кассы для Datathon 26. Бэкенд реализует API
из кейса, хранит задания в SQLite и извлекает кадры-доказательства из исходного видео.
React-приложение разрабатывается отдельно в `website/`.

**Текущий статус:** подключён обновлённый пакет `forte_service`: детектор
`forte_det.pt` и классификаторы `forte_door.pt` / `forte_safe.pt`. Распознаются
оставленные деньги/сумка, незаблокированный ноутбук при уходе, открытые дверь/сейф
и деньги предыдущего клиента. DEMO остаётся отдельным режимом проверки интерфейса.
Нормативные ссылки автора модели требуют проверки.

## Быстрый локальный запуск

Если зависимости уже установлены и `.env` создан, оба сервиса запускаются одной командой:

```bash
bash run.sh
```

Приложение: http://localhost:5173, API-документация: http://localhost:8000/docs.
Логи обоих процессов выводятся в один терминал;
Ctrl+C останавливает оба сервиса. Перед запуском остановите старые экземпляры.
Скрипт сам выбирает Python из корневого `.venv`; активация окружения не нужна.
На Windows можно выполнить `.venv\Scripts\python.exe scripts/dev.py`.

Python 3.11–3.13. Все команды выполняются из корня репозитория.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e './backend[dev]'
python -m pip install -r ml/requirements-cpu.txt
python -m pip install -r ml/requirements-service.txt
python scripts/init_env.py
uvicorn backend.app.main:create_app --factory --host 0.0.0.0 --port 8000 --workers 1
```

Windows PowerShell: создание окружения — `py -m venv .venv`, активация —
`.venv\Scripts\Activate.ps1`; остальные команды те же. Если активация недоступна,
запускайте `.venv\Scripts\python.exe -m uvicorn ...`.

Откройте **http://localhost:5173** после запуска React. Для запросов API используйте
`FORTE_API_KEY` из локального `.env`. API можно проверить через `/docs`, curl или
`scripts/smoke_test.py`. Режим анализа `demo` возвращает искусственные эпизоды с
настоящими кадрами загруженного видео: первый около 1-й секунды, второй — на 4-й
секунде, если ролик длиннее 4 секунд. Это не распознавание действий.
Режим анализа `demo` не является отдельной веб-страницей.

`init_env.py` не перезаписывает существующий `.env`. Если файл уже есть, переключите
`FORTE_ANALYZER_MODE` вручную. Ключ генерируется случайно, не выводится в логи и не
попадает в Git. Учётных записей и регистрации нет; ключ требуется по условиям кейса.

## Запуск моделей Forte

Присланные командой веса включены в репозиторий; остальные веса и видеодатасет
не отслеживаются Git. Для локального CPU-запуска установите ML-зависимости
в то же Python-окружение, что и бэкенд:

```bash
python -m pip install -r ml/requirements-cpu.txt
python -m pip install -r ml/requirements-service.txt
```

В `.env`:

```dotenv
FORTE_ANALYZER_MODE=plugin
FORTE_ML_CALLABLE=ml.service_inference:analyze
FORTE_MODEL_DIR=models
```

Перезапустите `bash run.sh`. В Docker зависимости устанавливаются при сборке:
`docker compose up --build -d`; веса доступны через read-only mount `models/`.
Для замены пакета положите три совместимых файла `forte_det.pt`, `forte_door.pt`,
`forte_safe.pt` в одну папку и укажите её через `FORTE_MODEL_DIR`.
После изменения `.env` пересоздайте контейнер через
`docker compose up -d --force-recreate`.

Алгоритм команды: [ml/forte_service.py](ml/forte_service.py), адаптер API:
[ml/service_inference.py](ml/service_inference.py). Устройство и CPU threads задаются
через `.env.example`. Порог детектора 0.25, 2 FPS и размеры входов 864/320/224
сохранены из пакета автора; старые переменные `FORTE_ML_FPS/CONF/IMGSZ` на него
не влияют. Старый адаптер `ml.inference:analyze` сохранён для сравнения. Подробнее:
[docs/ML_CONTRACT.md](docs/ML_CONTRACT.md).

При отсутствии весов или зависимостей загрузка отклоняется с `503`. Ошибка модели,
некорректный таймкод или невозможность прочитать видео дают `status=failed`, а не
ложный `no_violation`. `/ready` проверяет наличие файлов и библиотек; фактическая
загрузка весов проверяется через анализ контрольного видео.

Обработка не обращается к внешним AI API. Для распространённых библиотек выставлены
`HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`. ML-адаптер также обязан соблюдать
локальность; эти флаги не являются сетевой изоляцией произвольного Python-кода.
Распознавание лиц и анализ аудио не предусмотрены и не должны добавляться в адаптер.

## Фронтендеру

```bash
cd website
npm ci
npm run dev
```

Vite проксирует `/api` на `127.0.0.1:8000`. Готовый клиент:
[`website/src/api/analysis.js`](website/src/api/analysis.js).
Интерфейс запрашивает API-ключ в браузере, получает возможности сервера, загружает
видео, показывает ход задания и отображает результат с кадрами и источниками правил.
Ключ хранится только в состоянии вкладки. Подробный контракт: [docs/FRONTEND.md](docs/FRONTEND.md).

После `npm run build` сервер отдаёт единственный React-интерфейс из `website/dist`
по корневому адресу. Если сборки нет, используйте Vite на порту 5173.
В режиме `plugin` без доступной модели интерфейс сообщает о проблеме и
блокирует загрузку.

## API жюри

Все адреса `/api/*` защищены заголовком `X-API-Key`; проверка выполняется до разбора
файла. Спецификация OpenAPI: `/openapi.json`, интерактивная документация: `/docs`
(Swagger UI загружает свои ресурсы с CDN, сам API работает без CDN).

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
  -H 'X-API-Key: <ключ из .env>' \
  -F 'file=@/path/to/video.mov'

curl http://localhost:8000/api/v1/jobs/<job_id> \
  -H 'X-API-Key: <ключ из .env>'
```

`POST` возвращает HTTP `202` и `{"job_id":"..."}`. Статусы `GET`:
`processing`, `done`, `failed`. При `done` присутствуют `verdict` (`violation` /
`no_violation`) и `violations`. Каждый эпизод содержит тип, таймкод, описание,
1–3 JPEG-кадра в base64 и источник правила. Пример: [contracts/job.done.json](contracts/job.done.json).

Дополнительные адреса:

| Метод и адрес | Назначение |
| --- | --- |
| `GET /health` | Проверка доступности сервера, без ключа |
| `GET /api/v1/capabilities` | Режим, лимиты, наличие ML-модуля |
| `GET /api/v1/ready` | Проверка режима `plugin` и наличия модуля; не заменяет тест модели |
| `GET /api/v1/rules` | Правила, источники, применимость и ограничения |

Ошибки: `401` — ключ, `413` — размер, `415` — расширение, `422` — пустой файл /
неверная форма, `429` — очередь заполнена, `503` — ML не подключён.
Повреждённый файл с разрешённым расширением принимается в задание и завершается
`failed / invalid_video` после декодирования.

## Архитектура и ограничения

```text
React
              ↓ X-API-Key, multipart file
FastAPI → диск (видео) + SQLite (очередь, статусы, результаты)
              ↓ контролируемый subprocess на каждое задание
локальный ML-адаптер → валидация эпизодов → каталог правил → JPEG-доказательства
```

Один серверный процесс Uvicorn и один последовательный обработчик. Каждый анализ
изолирован в дочернем процессе, который принудительно завершается при тайм-ауте.
Лимит по умолчанию — 270 секунд **включая ожидание очереди**, отсчёт после сохранения
загрузки. Время сетевой загрузки зависит от соединения и не входит в этот лимит.
Очередь — до 6 незавершённых заданий, файлы — до 500 000 000 байт.
Настройки находятся в [.env.example](.env.example).

Задания и результаты переживают перезапуск. Прерванное активное задание помечается
ошибкой; ещё не начатые задания продолжаются, если не истёк срок. Частично
загруженные файлы при штатной ошибке удаляются. После аварийного завершения могут
остаться несвязанные файлы. Автоматического удаления видео нет: данные хранятся
локально в `data/`, каталог нужно удалить после хакатона согласно условиям кейса.
Не публикуйте датасет, тестовые видео, кадры или содержимое `data/`.

Каталог R01–R07 — возможные основания для проверки, **не перечень реализованных
ML-детекторов**. Подключённый алгоритм использует отдельные ML01/ML02; ссылки на
пункты для них взяты из скрипта автора и отмечены как неподтверждённые. Бэкенд связывает вывод адаптера с источником по `rule_id`, но
самостоятельно не распознаёт действия и не доказывает юридическую применимость.
Подробности: [docs/RULES.md](docs/RULES.md). Результаты измерений качества и
известные ошибки нужно дополнить после оценки на размеченной выборке.

## Проверки

```bash
python -m pytest -q backend/tests
ruff check --config backend/pyproject.toml backend scripts ml
```

Тесты генерируют собственный MOV и проверяют полный путь до декодируемого JPEG,
ключи, два вердикта, несколько эпизодов, ошибки адаптера, тайм-аут, восстановление,
лимиты и очистку неудачных загрузок. Датасет заказчика для тестов не нужен.

Проверка запущенного сервера через настоящий HTTP (без `--video` создаёт короткий
синтетический MOV):

```bash
python scripts/smoke_test.py
python scripts/smoke_test.py --video /path/to/control.mov --require-real
```

Можно добавить `--url https://your-service.example` для проверки публичного адреса
и `--expected-verdict violation` / `no_violation` для размеченного контрольного видео.

## Docker и сдача

Полный порядок проверок, запуск production-сборки и проверка сохранения заданий
после перезапуска: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

```bash
python scripts/init_env.py
docker compose up --build
```

Образ собирает React и запускает API на `8000`. ML-зависимости уже включены в Dockerfile;
для настоящего анализа переключите режим на `plugin`. Сборка образа требует
интернета; ранние веса уже входят в репозиторий, обработка локальна.

**По кейсу требуется публичный URL, одного репозитория недостаточно.** Разместите
сервис на доступном компьютере/сервере и настройте HTTPS reverse proxy или одобренный
организаторами туннель. Прокси должен пропускать файлы до 500 МБ и не обрывать
длительную загрузку. Пример: [deploy/nginx.conf](deploy/nginx.conf).
Передайте жюри публичный адрес UI, базовый адрес API и ключ отдельным сообщением.
Не помещайте ключ в README или историю Git.

Перед сдачей: проверить модель через публичный API на MOV,
проверить кадры и таймкоды, убедиться, что режим `plugin`, и оставить компьютер
включённым. Публикация сервиса и отправка ключа в рамках этой реализации не выполнены.
