# Подключение React к API

Бэкенд запускается на `http://127.0.0.1:8000`. В Vite уже добавлен прокси `/api`.
Стили и компоненты интерфейса остаются у фронтендера.

```jsx
import { createAnalysisClient } from './api/analysis'

const controller = new AbortController()
const client = createAnalysisClient({ apiKey: keyFromInput })

const capabilities = await client.capabilities(controller.signal)
// mode === 'demo': обязательно показать, что результаты искусственные.
// model_available === false: предложить подключить ML, не показывать успех анализа.

const { job_id } = await client.analyze(selectedFile, controller.signal)
const result = await client.waitForJob(job_id, {
  signal: controller.signal,
  onUpdate: job => {
    setStage(job.stage)
    setProgress(job.progress)
  },
})
setResult(result)
```

Все ошибки ловите через `try/catch` и показывайте пользователю. `AbortController`
отменяет сетевые запросы и ожидание на клиенте, но не уже принятое сервером задание.
При размонтировании компонента вызовите `controller.abort()`.

Ключ можно вводить в поле интерфейса и держать в React state. Пользователи и логин
не нужны. Нельзя прятать секрет в `VITE_API_KEY`: он окажется в публичной сборке.
При другом origin передайте `baseUrl` клиенту и добавьте origin интерфейса в
`FORTE_CORS_ORIGINS` на сервере. При общей сборке используйте относительные адреса.

Файл отправляется `FormData` с полем **file**; `Content-Type` вручную не задавайте,
браузер добавляет multipart boundary. Обязательный формат — MOV, разрешены также
MP4, M4V, AVI. Лимит берите из capabilities. Повторный POST создаёт новое задание,
поэтому отключайте кнопку после нажатия.

Статусы: `processing`, `done`, `failed`. Дополнительные стадии:

| stage | Текст |
| --- | --- |
| queued | Ожидание обработки |
| validating | Проверка видео |
| analyzing | Анализ видео |
| extracting_evidence | Подготовка кадров |
| completed | Готово |
| failed | Ошибка обработки |

`progress` отражает стадию процесса, а не процент просмотренных кадров.
При `failed` показывайте `error.message`; вердикта у ошибки нет.
При `done`: `no_violation` → «Нарушение не обнаружено»;
`violation` → «Обнаружены признаки возможных нарушений».
Если `mode=demo`, вместо реального вердикта покажите «DEMO — тестовый результат».

Кадры:

```jsx
<img
  src={`data:image/jpeg;base64,${frame.image_base64}`}
  alt={`Кадр ${frame.timestamp_sec.toFixed(2)} с`}
/>
```

Для просмотра оригинала создайте `URL.createObjectURL(selectedFile)` и используйте
его в единственном `<video>` внутри `AnalysisResult`. Нативный `controls` не нужен:
компонент предоставляет одну общую шкалу и кнопки воспроизведения.
Очищайте object URL через `URL.revokeObjectURL`. Некоторые MOV-кодеки не поддерживаются
браузером; это не мешает серверному анализу и отображению JPEG.

Показывайте `description`, `rule.document`, `rule.section`, `rule.url`,
`alternative_explanation`, `missing_data`, `limitations`. Уверенность модели
не подписывайте как вероятность нарушения закона.

Единственный пользовательский интерфейс — React: `http://localhost:5173` при разработке.
После сборки React (`npm run build` в website) FastAPI отдаёт `website/dist` по `/`.

Результаты отображаются компонентом `src/components/AnalysisResult.jsx`. Эпизоды
сортируются по таймкоду и нумеруются, включая повторения одного правила. Кнопки
эпизодов и отметки шкалы выбирают нужное объяснение справа от плеера и запускают
ограниченный фрагмент. Выбор эпизода не прокручивает страницу. Список всех эпизодов
находится под плеером и объяснением. После анализа форма загрузки скрывается;
«Новое видео» возвращает её. Переход до загрузки метаданных
откладывается до готовности плеера. Если браузер не поддерживает кодек, интерфейс
предлагает проверить кадры. Предыдущий/следующий эпизод и выделение текущей карточки
помогают проверить несколько событий в одном видео.

Регрессионные проверки навигации: `npm test` из `website/`. Они используют
синтетический DOM и имитируют медиаплеер; декодирование реального видео зависит
от кодека и браузера.

Внутри плеера есть общая шкала эпизодов. У каждого эпизода отдельная кнопка с номером.
Близкие отметки размещаются рядом без перекрытия, включая одинаковые таймкоды;
каждая выбирается одним нажатием. Если места не хватает, добавляется ряд кнопок.
Ни один эпизод не удаляется. Выбор отметки
выделяет начало и конец фрагмента. При наличии `start_sec` и `end_sec` используются
границы модели. Если их нет, показывается явно подписанное контекстное окно ±1 с,
обрезанное по длительности видео. Это не утверждение о длительности нарушения.
В режиме фрагмента воспроизведение останавливается на конце диапазона. Нажатие на
само видео, кнопка «Всё видео» и перемотка общей шкалы включают обычный просмотр
без границ. Выбранное объяснение при этом сохраняется. «Смотреть эпизод» снова
включает диапазон. Границы можно менять в раскрываемом блоке объяснения.
На широком экране рабочий блок подстраивается под высоту окна; длинный список и
подробности прокручиваются внутри своих панелей. На узком экране блоки располагаются
вертикально.

Заголовок результата — «Анализ · имя файла». В правой панели отображаются
«Нарушение N», тип и краткое объяснение; стрелки переключения расположены справа
от заголовка нарушения. Настройка диапазона скрыта под «Изменить границы».
DEMO помечается короткой подписью «Тестовые данные» внизу, без вводных баннеров;
его примеры описывают сценарий, а не детали интеграции.

Кнопки плеера расположены по центру; отдельная подпись диапазона и дублирующие
таймкоды под шкалой убраны. «Новое видео» выделено основной акцентной кнопкой.
В нижнем списке полностью отображаются тип, наблюдаемое действие, источник и
таймкод каждого нарушения, без обрезки текста многоточием. Вся карточка остаётся
кнопкой: одно нажатие выбирает нарушение и запускает его фрагмент в том же плеере.
