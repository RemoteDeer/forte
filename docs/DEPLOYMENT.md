# Проверка развёртывания

Все команды выполняются из корня репозитория с установленными зависимостями
Python и `npm ci` в `website/`. Для контейнера нужен запущенный Docker с Compose.

## 1. Проверить код

```bash
python -m pytest -q backend/tests
ruff check --config backend/pyproject.toml backend scripts ml
npm --prefix website run lint
npm --prefix website test
npm --prefix website run build
docker compose config --quiet
```

## 2. Запустить production-сборку

Остановите локальный `run.sh`, если он занимает порт 8000.
Создайте `.env` через `python scripts/init_env.py`, если файла ещё нет.
Для искусственных результатов можно явно использовать `--demo`.
Для настоящего анализа настройте ML по [ML_CONTRACT.md](ML_CONTRACT.md).

```bash
docker compose up --build -d --wait --wait-timeout 120
docker compose ps
python scripts/smoke_test.py --url http://localhost:8000 --check-frontend
```

Откройте **http://localhost:8000**. В production интерфейс и API работают на одном
порту; Vite запускать не нужно. Ключ возьмите из локального `.env`.

Smoke-тест проверяет `/health`, отказ при отсутствующем и неверном ключе,
production HTML и JS/CSS, загрузку MOV, завершение задания, согласованность вердикта
и эпизодов, а также декодирование JPEG. Без `--video` создаётся синтетический ролик
на шесть секунд; в DEMO ожидаются два искусственных эпизода. Тест не оценивает
качество распознавания модели и не проверяет браузерный видеокодек.

## 3. Проверить сохранение после перезапуска

Скопируйте ID из строки `Accepted job ...` предыдущего теста.

```bash
docker compose restart app
docker compose up -d --wait --wait-timeout 120
python scripts/smoke_test.py --url http://localhost:8000 --check-frontend --job-id <JOB_ID>
```

Результат и JPEG должны остаться доступны. `--job-id` проверяет сохранённое задание
без новой загрузки. Данные находятся в примонтированном каталоге `data/`.

## 4. Проверить публичный адрес и модель

После настройки сервера/туннеля и HTTPS:

```bash
python scripts/smoke_test.py --url https://YOUR_DOMAIN --check-frontend --video /path/to/violation.mov --require-real --expected-verdict violation
python scripts/smoke_test.py --url https://YOUR_DOMAIN --video /path/to/clean.mov --require-real --expected-verdict no_violation
```

`FORTE_API_KEY` в окружении теста должен совпадать с ключом сервера. Сам ключ
не передаётся в URL и не выводится тестом. Для реальной модели дополнительно
проверьте `/api/v1/ready` с заголовком `X-API-Key`: он должен вернуть 200.
В DEMO этот адрес намеренно возвращает 503.

Проверьте через браузер загрузку реального MOV, оба эпизода, воспроизведение
диапазона ±1 с, свободное воспроизведение всего видео и кнопку «Новое видео».
Дополнительно загрузите репрезентативный большой ролик: маленький синтетический
файл не проверяет ограничения reverse proxy, пропускную способность или качество ML.

## Логи и остановка

```bash
docker compose logs -f --tail 100 app
docker compose stop
```

`docker compose stop` сохраняет контейнер и данные. Для повторного запуска:
`docker compose up -d --wait`. После изменения `.env` используйте
`docker compose up -d --force-recreate --wait`: обычный restart не обновляет
окружение контейнера.

Это ручной pipeline проверки и развёртывания. Автоматическая публикация из GitHub,
публичный сервер, DNS и TLS должны быть настроены отдельно под выбранную площадку.

## Результат локальной проверки — 18.10.2026

- Backend: 36 тестов прошли; frontend: 24 теста прошли; оба линтера и Vite build прошли.
- Production Docker image с YOLO собран на Node 24 / Python 3.12; Compose дождался
  healthy. `pip check` не обнаружил несовместимых зависимостей.
- Проверены HTTP-доступ к React и его JS/CSS, `/health`, отказ при неверном ключе,
  загрузка MOV и реальное выполнение YOLO в режиме plugin. Положительный путь двух
  ML-правил и JPEG проверен интеграционной фикстурой в тестах.
- Проверены 404 для неизвестного задания, 415 для расширения, 422 для пустого файла,
  413 для запроса с заявленным размером выше лимита и `invalid_video` для повреждённого MOV.
- После перезапуска контейнера весь JSON завершённого задания, включая JPEG,
  остался идентичным. Проверка проводилась с отдельной SQLite и тестовым ключом.
- В образе отсутствуют локальные `.env` и `.git`.

Дополнительно после подключения ML:

- `/api/v1/ready` вернул 200 в контейнере с настоящими весами.
- Реальный MOV обработан также в отдельном Docker-контейнере с `--network none`.
- После перезапуска контейнера сохранённый результат настоящего ML остался идентичным.
- Локально проверены четыре MOV: три коротких за 22–25 с, ролик 142,5 с за 204,6 с.
  Все четыре вердикта модели — `no_violation`. Качество без эталонной разметки не оценено.
- Сигналы, эпизоды и вердикт адаптированного детектора совпали с исходным скриптом
  на одном реальном MOV. Подробности и версии: [ML_CONTRACT.md](ML_CONTRACT.md).

Качество распознавания по размеченной выборке, публичный HTTPS, загрузка файла
около 500 МБ и воспроизведение кодека в настоящем браузере этой проверкой не подтверждены.
